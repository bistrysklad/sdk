# Backend → браузер по SSE

`server.ts` открывает один WebSocket со складом. При событии перечитывает
опубликованный каталог выбранного профиля, затем рассылает `catalog.changed`
браузерам. `index.html` использует обычный `EventSource('/events')` и перечитывает
`/catalog`. Токен компании, исходные события и внутренние курсоры браузеру не выдаются.

Из корня SDK после `npm ci && npm run build`:

```sh
# Передайте значения через окружение, не сохраняйте токен в файлы проекта.
# BISTRYSKLAD_TOKEN — API-токен; BISTRYSKLAD_PROFILE_ID — ваш профиль каталога.
node examples/server.ts
```

Адрес: http://127.0.0.1:3000. По умолчанию склад https://bistrysklad.ru;
`BISTRYSKLAD_URL` переопределяет адрес, `PORT` — локальный порт.
Профиль должен быть включён, товары опубликованы. Без публикаций каталог пуст.

Пример предназначен для публичной витрины одной компании и выдаёт только
`id/name/price/available`. Для личного кабинета добавьте свою проверку сессии
и прав на компанию к `/catalog` и `/events`. Не открывайте endpoint со всеми
товарами компании анонимным посетителям. Для нескольких компаний создавайте
отдельные подписки и направляйте сообщения только их авторизованным клиентам.

В примере снимок и курсор живут в памяти: после рестарта он загружает свежий
каталог с безопасной начальной позицией. Для постоянной синхронизации храните
результат обработки и курсор одной транзакцией своей БД. Пример ограничен 5000
карточками и 100 браузерными подключениями; большому каталогу нужен кеш,
постраничное чтение и объединение частых обновлений. Фотографии требуют
отдельного авторизованного прокси, здесь выводится текстовый каталог.
