# Realtime: контракт и восстановление

Три маршрута требуют Bearer-токен компании. SSE также поддерживает сессию
приложения склада. Токен передаётся только в заголовке `Authorization`.

| Маршрут | Назначение |
| --- | --- |
| `GET /api/v1/events?after=…&limit=100` | JSON `EventsPage`; `limit` от 1 до 200 |
| `GET /api/v1/events/stream?after=…` | SSE; без query используется `Last-Event-ID` |
| `GET /api/v1/events/ws?after=…` | WebSocket Upgrade; только приём событий |

Без `after` возвращается текущий курсор и пустая история. Курсор — непрозрачная
строка компании; передавайте её без изменений. JSON-страница содержит `events`,
`cursor` последнего прочитанного события, `headCursor`, `hasMore`, `retentionEvents`.
При `hasMore` продолжите с `cursor`. Журнал хранит последние 20 000 событий,
без гарантии срока в днях. Новый склад начинает с пустого журнала.

## Сообщения

WebSocket передаёт JSON. SSE передаёт тот же JSON в `data`, тип в `event`,
курсор бизнес-события в `id`:

```text
id: synthetic-company:42
event: product.updated
data: {"type":"product.updated","cursor":"synthetic-company:42","entityId":"synthetic-product","source":"products","occurredAt":"2026-10-06T00:00:00.000Z"}

```

`ready` подтверждает начальную позицию. `heartbeat` приходит примерно каждые
15 секунд. У них есть `type` и `cursor`, но нет SSE `id`. При ошибке после
начала потока сервер отправляет `{type:"error",status,code,message}` и закрывает
соединение. До начала потока ошибка имеет обычный HTTP-статус и JSON.
SDK отдаёт только бизнес-события; управляющие сообщения доступны через `onStatus`.

События — сигналы об изменении. Загрузите актуальные данные через обычный API.
`source` — таблица-источник, диагностическая строка; не стройте бизнес-правила
на полном фиксированном перечне её значений. Для `entityId:null` обновите весь
затронутый каталог. Изменения остатков/резервов могут затронуть доступность
нескольких комплектов, поэтому обновление каталога витрины часто удобнее карточки.

## Надёжная обработка

1. Получите начальный `cursor` через `events.list()`.
2. Загрузите снимок нужного каталога.
3. Начните подписку с `after: cursor`; изменения во время загрузки будут дочитаны.
4. Выполните обработку события и сохраните его курсор. После рестарта используйте его.

SDK продвигает внутренний курсор, когда потребитель запрашивает следующее
событие. Если обработка бросила исключение, завершите подписку и возобновите её
с последнего сохранённого курсора. Для обработки и курсора в собственной БД
используйте одну транзакцию. Доставка допускает повторы, эффекты должны быть
идемпотентными. Журнал не заменяет полную историю бухгалтерских операций.

`EVENT_CURSOR_INVALID` (400) означает чужой/неверный курсор,
`EVENT_CURSOR_FUTURE` (409) — курсор опережает журнал,
`EVENT_CURSOR_EXPIRED` (409) — сохранённая история закончилась. Эти ошибки
завершают iterator. Для истёкшего курсора повторите начальную загрузку снимка;
SDK сам не пропускает потерянные события. Ошибки 401/403 тоже не повторяются.

## Настройки подписки

| Опция | По умолчанию | Значение |
| --- | --- | --- |
| `after` | Текущая позиция | Курсор для возобновления |
| `signal` | Нет | Отмена подключения, чтения и повторов |
| `reconnect` | `true` | Восстановление при временном сбое |
| `maxReconnectAttempts` | `10` | Последовательные разрывы без бизнес-событий |
| `baseDelayMs` / `maxDelayMs` | `500` / `30000` | Экспоненциальная задержка |
| `connectTimeoutMs` | `10000` | Получение токена и подключение |
| `idleTimeoutMs` | `45000` | Максимальное отсутствие сообщений |
| `onStatus` | Нет | `connected`, `heartbeat`, `reconnecting` |

429 учитывает `Retry-After`, когда сервер его передал. Уменьшите частоту
подключений и соблюдайте паузу. Подключение учитывается как один
обычный API-запрос; доставка сообщений и heartbeat не считаются отдельными HTTP-запросами.
Сервер разрешает до 10 активных потоков компании и 200 на процесс. Отозванный
токен/сессия отключаются при повторной проверке в пределах примерно 30 секунд.

WebSocket SDK буферизует до 256 сообщений. Если потребитель не успевает,
соединение возобновляется с последнего обработанного курсора. Размер кадра
ограничен 64 KiB. Сервер также ограничивает исходящий буфер и время ожидания
SSE drain. Настройте proxy buffering off и поддержку WebSocket Upgrade; эти
настройки уже предусмотрены в прокси склада.

Нативный браузерный `EventSource` не позволяет задать Authorization. Для своего
сайта используйте [SSE endpoint собственного backend](../examples/README.md).
В сервисных интеграциях используйте Node WebSocket или SDK SSE с fetch.
