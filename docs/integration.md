# Подключить сайт к Быстрому складу

Склад хранит каталог, фотографии, цены, остатки и заказы. Backend сайта
получает данные через SDK и отдаёт посетителю нужные поля. Токен остаётся
на backend. Браузер получает обновления с вашего сервера, например через SSE.

## 1. Установка и доступ

```sh
npm install @bistrysklad/sdk
```

Примеры описывают SDK **0.2.0**. Node.js ≥22.18. Владелец пространства создаёт токен в
**Настройки → API-токены**. Сохраните `BISTRYSKLAD_TOKEN` в окружении сервера.
Обычный токен разрешает чтение каталога, фотографий, витрин и событий.
Для записи товаров включите **Изменение каталога**, для чтения и создания заказов —
**Работа с заказами** в настройках этого токена. Включайте только нужные права.

Для конкретной витрины сохраните её ID в `BISTRYSKLAD_PROFILE_ID`.
Получить доступные витрины можно через `sklad.catalogProfiles.list()`.

```ts
import { createBistryskladClient } from "@bistrysklad/sdk";

const token = process.env.BISTRYSKLAD_TOKEN;
if (!token) throw new Error("Задайте BISTRYSKLAD_TOKEN на сервере");
const sklad = createBistryskladClient({
  baseUrl: "https://bistrysklad.ru",
  token,
  timeoutMs: 10_000,
});
```

Каждая команда подтверждает сохранение через `{result, revision}`.
Для чтения используйте отдельные страницы и карточки. `revision` относится
к данным пространства; курсор событий — отдельное значение.

## 2. Каталог конкретной витрины

```ts
const profileId = process.env.BISTRYSKLAD_PROFILE_ID;
if (!profileId) throw new Error("Задайте BISTRYSKLAD_PROFILE_ID");
const page = await sklad.catalogProfiles.catalog(profileId, {
  limit: 50, offset: 0, sort: "default",
});
console.log(page.products, page.nextOffset, page.version);
```

Профиль выбирает склады и тип цены; публикация и порядок учитываются сервером.
Используйте `sort: "default"`, чтобы сохранить настроенный порядок показа.
`nextOffset: null` означает конец списка. Если версия изменилась во время
чтения нескольких страниц, перечитайте снимок: страницы разных версий могут
описывать разные состояния.

`workspace.products.list()` предназначен для рабочего каталога пространства,
а `catalogProfiles.catalog(profileId)` — для выбранной витрины. Пустое
пространство возвращает пустой каталог. Проверьте публикацию, профиль, остаток
и тип цены, если товар не попал в витрину.

Фотографии хранятся на складе. `sklad.images.get(imageId)` возвращает `Blob`;
передайте байты через маршрут вашего backend или сохраните в своём CDN.
Проверяйте, что фотография принадлежит опубликованному товару вашей витрины,
прежде чем отдавать её посетителю. Токен доступа в URL изображения не нужен.

## 3. Создание заказа и защита от дублей

```ts
const saved = await sklad.orders.create({
  customer: customerName,
  warehouseId,
  channel: "website",
  externalSource: "website",
  externalId: checkoutId,
  reserveMode: "available",
  items: [{ productId, quantity: 1 }],
}, {
  idempotencyKey: persistedCommandKey,
  retry: { maxAttempts: 3, baseDelayMs: 200, maxDelayMs: 2000 },
});
console.log(saved.result.id);
```

Значения приходят из вашего checkout и настроек пространства. Backend сайта
проверяет состав и разрешённые товары; цену и склад нельзя принимать на веру
из браузера. При отсутствии `price` используется серверная логика определения
цены; для выбранной витрины задайте подходящий `priceTypeId`, если нужно.

Создайте и сохраните ключ **до** обращения к складу: один ключ на одну
логическую команду. UUID генерируется SDK автоматически, но сохранённый ключ
нужен для повтора после перезапуска вашего сервера. Повторяйте ту же команду,
тело и режим ответа. Изменение тела требует нового ключа.

`externalSource` и `externalId` связывают заказ сайта с заказом склада;
используйте постоянный ID checkout. Не создавайте новый checkout при повторе.
Приём внешних заказов должен быть доступен в тарифе пространства.

`reserveMode: "none"` создаёт заказ без резерва, `available` резервирует
доступную часть, `full` требует полного резерва. Физический остаток меняется
при проведении соответствующей операции. Заказ на будущее может содержать
`fulfillmentAt` и `fulfillmentTimeZone`; вводите фактическое выбранное время.

## 4. Статусы и движения

Загрузите модели через `workspace.salesWorkflows.list()` и текущий заказ через
`workspace.orders.get(orderId)`. Используйте доступный переход:

```ts
await sklad.orders.transition(orderId, { transitionId }, {
  idempotencyKey: persistedTransitionKey,
});
```

Модель задаёт допустимые переходы и действия с резервом/остатком. Не подставляйте
ID статусов из чужого пространства и не считайте название статуса универсальной
командой отгрузки. Установленная версия модели заказа сохраняет его правила.

## 5. Обновления через сокеты

```ts
import { subscribeToEvents } from "@bistrysklad/sdk/node";

const stop = new AbortController();
for await (const event of subscribeToEvents(
  { baseUrl: "https://bistrysklad.ru", token },
  { after: savedCursor, signal: stop.signal },
)) {
  await refreshAffectedData(event);
  await persistCursor(event.cursor);
}
```

Один backend держит подписку, обновляет кеш нужной витрины и уведомляет
браузеры. Событие сообщает об изменении; актуальные данные читайте отдельным
запросом. Курсор сохраняйте после успешной обработки. Допускайте повторную
доставку. При истёкшем курсоре загрузите новый снимок.

Для начальной загрузки сначала получите `(await sklad.events.list()).cursor`,
затем снимок и подписку с этой позиции. [Рабочий пример сервера и браузера](https://github.com/bistrysklad/sdk/blob/main/examples/README.md)
и [полный протокол восстановления](https://github.com/bistrysklad/sdk/blob/main/docs/realtime.md) показывают этот порядок.

## 6. Дополнительные поля с типами вашей компании

```sh
npx bistrysklad generate --url https://bistrysklad.ru --out src/bistrysklad
npx bistrysklad generate --url https://bistrysklad.ru --out src/bistrysklad --check
```

Импортируйте `createCompanyClient` из созданного `client.ts`. Поля участвуют
в записи, чтении, фильтрации, сортировке и CSV. Генератор создаёт локальные
типы, не сохраняет токен и не требует сети при сборке. Для каждой компании
используйте отдельный каталог. Коды полей стабильны; после изменения схемы
повторите генерацию и проверьте diff.

## 7. Ошибки и нагрузка

Чтения и команды по умолчанию имеют до трёх попыток, включая первую.
SDK повторяет сетевые ошибки и HTTP 429, 502, 503, 504; учитывает `Retry-After`.
Без этого заголовка пауза растёт от 200 мс до 2 с. Общий таймаут — 30 с,
включая ожидание повторов. Ошибки 400, 401, 402, 403 и 409 не повторяются.
Повторы записи сохраняют ключ и байты команды. Настройки клиента можно
переопределить для конкретного вызова: `retry: { maxAttempts: 1 }` отключает повторы.

`402 TRIAL_EXPIRED` означает окончание бесплатного месяца. Кабинет сохраняет
просмотр и экспорт, API-токены приостановлены до подключения платного тарифа.
Повтор запроса без изменения тарифа не поможет.

`429 WORKSPACE_BUSY` просит снизить частоту или параллельность обращений этого
пространства. SDK учитывает `Retry-After`. Ставьте задачи в очередь на своём
backend; повтор каждого запроса без паузы увеличивает нагрузку.
Тарифы не устанавливают числовых квот запросов и хранения.

При таймауте команда могла сохраниться. Повторите её с прежним ключом или
проверьте заказ по сохранённому ID. [Таблица ошибок и действий](https://github.com/bistrysklad/sdk/blob/main/docs/errors.md).

Готовые функции с настоящими сигнатурами находятся в
[examples/integration.ts](https://github.com/bistrysklad/sdk/blob/main/examples/integration.ts). Они компилируются в CI.

## 8. Как читать ответы и разбирать ошибки

У каждого метода в справочнике есть описание поведения, таблицы параметров и
полей, допустимые значения и раздел **Ответы и примеры ошибок**. Эти блоки
генерируются из того же OpenAPI, который отдаёт сервер: исправление описания
в серверном контракте обновляет и справочник, и интерактивную страницу.

HTTP-статус сообщает класс результата, а `error.code` — причину, которую можно
обрабатывать в коде. `error.message` предназначен для человека и может меняться;
не сравнивайте его со строковой константой. Ошибка проверки полей и временная
перегрузка требуют разных действий: исправления запроса и повторения после паузы.

Ниже — примеры из OpenAPI метода создания заказа. Сообщения иллюстративные;
при разборе ответа ориентируйтесь на HTTP-статус и машинный код.

Точные JSON-примеры: [создание заказа в справочнике](https://docs.bistrysklad.ru/reference.html#order.create).

### Обработка ошибки в SDK

```ts
import { BistryskladError } from "@bistrysklad/sdk";

try {
  await sklad.orders.create(command, { idempotencyKey: savedKey });
} catch (error) {
  if (!(error instanceof BistryskladError)) throw error;
  if (error.status === 400) {
    // Исправьте данные заказа и создайте ключ для исправленной команды.
    reportInvalidOrder(error.code, error.message);
  } else if (error.status === 429) {
    // Поставьте ту же команду в очередь; не начинайте немедленный цикл повторов.
    scheduleRetry(command, savedKey, error.rateLimit.retryAfterMs);
  } else {
    // При таймауте результат записи может быть неизвестен: сохраняйте прежний ключ.
    reportIntegrationError(error.status, error.code);
  }
}
```

`reportInvalidOrder`, `scheduleRetry` и `reportIntegrationError` — функции вашего
приложения. Автоматические повторы SDK задаются через `retry`; не добавляйте
поверх них бесконечный цикл. Если сервер вернул конфликт идемпотентности,
сначала выясните, какой запрос был связан с ключом.

У каждого метода справочника есть пример **Тот же запрос через @bistrysklad/sdk**.
Используйте настроенный выше клиент `sklad`; имена методов берутся из OpenAPI
и проверяются при генерации пакета. [Пакет npm](https://www.npmjs.com/package/@bistrysklad/sdk)
и [README SDK](https://github.com/bistrysklad/sdk) содержат дополнительные примеры.

Поиск в справочнике понимает названия тем, пути, поля, пояснения и коды ошибок.
Например: `резерв`, `fulfillmentAt`, `фото`, `ошибка 409`, `WORKSPACE_BUSY`.
Несколько слов сужают выбор: метод должен содержать каждое из них. Меню
раскрывается на найденных темах, а после очистки поиска возвращается к прежнему виду.
