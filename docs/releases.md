# Выпуск и обновление SDK

Репозиторий самостоятельный: исходники SDK, публичный OpenAPI, синтетические
тесты и документация. Клиентские схемы компаний и токены в него не входят.

1. Обновите публичный `contract/openapi.json` вместе с совместимым backend.
2. Выполните `npm ci`, `npm run generate`, `npm run generate:check`, `npm test`.
3. Обновите версию и `CHANGELOG.md`, выполните `npm pack --dry-run`, проверьте
   состав архива. Он содержит dist, документацию и примеры.
4. Закоммитьте исходники и создайте тег версии. Пользовательский проект может
   установить собранный `.tgz` через обычный `npm install`.

Публичная публикация в npm ещё не настроена. Для неё требуется право на scope
`@bistrysklad`, решение о лицензии и настройка npm Trusted Publishing с GitHub
Actions. Не добавляйте постоянный npm-токен в репозиторий. После настройки
публикации используйте provenance, проверенный тег и явный `--access public`.

Основной пакет содержит ESM/CJS и оба графа деклараций. CLI требует Node ≥22.18;
генератор обновляет только принадлежащие ему файлы и проверяет совместимость
методов SDK с полученным контрактом. Изменение company schema не требует
нового выпуска SDK: перегенерируйте локальные типы компании.

После проверок этой серии публикуется GitHub prerelease `v0.1.0-beta.5`
с архивом `bistrysklad-sdk-0.1.0-beta.5.tgz`. Это канал доставки до настройки
npm registry. Зависимости интеграций закрепляются точным URL и integrity в
package-lock; совместимый backend выпускается вместе с новым контрактом.
Компактный режим требует поддержки сервера; default full сохраняет совместимость.
