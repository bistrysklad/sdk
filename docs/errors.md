# Ошибки и восстановление

```ts
import { BistryskladError } from "@bistrysklad/sdk";
try {
  await executeCommand();
} catch (error) {
  if (!(error instanceof BistryskladError)) throw error;
  console.log(error.status, error.code, error.idempotencyKey,
    error.rateLimit.retryAfterMs);
}
```

Не записывайте токены и персональные данные из тела заказа в логи.

| Код / статус | Что делать |
| --- | --- |
| `UNAUTHORIZED`, 401 | Проверьте токен, его отзыв и адрес API. Получите новый токен у владельца. |
| `SCHEMA_COMPANY_MISMATCH`, 403 | Токен и сгенерированная схема принадлежат разным пространствам. |
| `PLAN_FEATURE_REQUIRED`, 402 | Проверьте доступность нужной функции тарифу пространства. |
| `WORKSPACE_BUSY`, 429 | Уменьшите число параллельных обращений и соблюдайте Retry-After. |
| `SERVICE_BUSY`, 429 | Сервер ограничил обработку; повторите после указанной паузы. |
| `EVENT_CONNECTION_LIMIT`, 429 | Повторно используйте одну серверную подписку; закройте лишние. |
| `INVALID_REQUEST`, 400 | Исправьте поля, ID связей и типы. Повтор без изменений не помогает. |
| `IDEMPOTENCY_CONFLICT`, 409 | Ключ уже связан с другим запросом или режимом ответа. |
| `TIMEOUT`, `NETWORK_ERROR`, статус 0 | Ответ неизвестен. Команду повторяйте с прежним ключом. |
| `ABORTED`, статус 0 | Запрос отменён AbortSignal. Запись могла уже сохраниться. |
| `COMPACT_RESPONSE_UNSUPPORTED` | Старый сервер не подтвердил minimal-формат. Сохраните ключ, проверьте данные. |
| `EVENT_CURSOR_EXPIRED` | Получите курсор, свежий снимок и восстановите подписку. |
| `EVENT_CURSOR_INVALID` | Проверьте формат курсора и компанию; не используйте revision вместо cursor. |
| 502, 503, 504 | Ограниченный повтор с паузой и тем же ключом команды. |

Для команд автоматический UUID действует в пределах вызова SDK; используйте
собственный сохранённый ключ для восстановления задания после рестарта.
`rateLimit.limit` и `remaining` могут быть `null`: текущий сервер не сообщает
тарифные квоты. `retryAfterMs` остаётся полезным при защите от перегрузки.
Счётчик API — статистика принятых запросов, обновляется пакетами примерно раз
в 5 секунд; аварийная остановка процесса может потерять последний пакет.

Параметры повторов задаются через `retry`; `timeoutMs` — общий deadline.
`CallOptions.signal` отменяет запрос и ожидание повторов. Отмена не откатывает
уже подтверждённую серверную транзакцию.
